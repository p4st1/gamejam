### Как запустить автотесты
```bash
"<путь к Godot>" --headless --path . --script res://tests/test_player_controller.gd
```
Код выхода 0 — все проверки пройдены. Тесты: `test_player_controller`, `test_menu_settings`, `test_audio`,
`test_hospital_kit`, `test_hospital_service`, `test_m03_blockout`.

**Правило для тестов:** скрипт теста (`extends SceneTree`) компилируется раньше, чем регистрируются
автозагрузки. Поэтому в тестах сцены грузятся через `load()` во время выполнения (не `preload`),
а классы, ссылающиеся на автозагрузки (например `Player`), не указываются как типы переменных.
Перед `quit()` тест останавливает звук (`root.propagate_call(&"stop")` и короткая пауза), иначе
движок сообщает об «утечке» воспроизведений.

**Правило для скриптов сцен:** не использовать `preload` внутри функций скриптов, которые входят
в загружаемые уровни (игрок, реквизит): уровни грузятся в фоновом потоке (`Game.change_scene`), и
такой `preload` оставляет незакрытые служебные объекты загрузчика. Загружать через `load()` в `_ready`. Godot у создателя установлен через Steam:
`~/Library/Application Support/Steam/steamapps/common/Godot Engine/Godot.app/Contents/MacOS/Godot`.

## Технические принципы

1. Модульность: каждая система — отдельная сцена/скрипт с понятным интерфейсом.
2. Композиция вместо глубокого наследования (компоненты-ноды: Health, Interactable, Weapon).
3. Слабая связанность через сигналы и небольшой глобальный EventBus.
4. Данные отдельно от кода: оружие, реплики, параметры ИИ — в `Resource` (.tres).
5. Никакой оптимизации «на будущее», но бюджет производительности фиксируется с прототипа.
6. Версия движка фиксируется на прототипе и не меняется без причины.

## Ключевые архитектурные узлы (будут описаны отдельно перед реализацией)

| Система | Подход (черновик) |
|---|---|
| Контроллер игрока | `CharacterBody3D` + отдельные ноды для камеры, оружия, взаимодействия |
| Оружие | Hitscan через `RayCast3D`/`PhysicsDirectSpaceState3D`, параметры в `WeaponData` Resource |
| ИИ | Простая конечная машина состояний + `NavigationAgent3D`; укрытия — размеченные точки на уровне |
| Повествование | Триггер-зоны → `SequenceRunner`, выполняющий шаги (реплика, анимация, ожидание, событие) |
| Диалоги | Данные в Resource/JSON, субтитры, приоритет реплик, радио-фильтр на шине аудио |
| Сохранение | Чекпоинты: сериализация минимального состояния миссии |
| Воспоминания | Сцена памяти подгружается заранее (`ResourceLoader.load_threaded_request`), переход — через пост-обработку (`WorldEnvironment`: десатурация, виньетка) + аудио-шину «Memory» с low-pass; игрок переносится в сцену памяти и возвращается в ту же точку. Запускается обычным шагом `SequenceRunner` |
| Аудио | Шины: Master / SFX / Voice / Radio / Music / Ambience; реверб-зоны |

## Техописание: контроллер игрока v0.1 — В РАЗРАБОТКЕ

**Задача:** базовое передвижение и обзор от первого лица. Первая система прототипа; на неё опираются
оружие, взаимодействие, СИЗ, перенос тяжестей и симптомы.

**Требования:**
- Ходьба ~3,0 м/с, бег ~5,5 м/с (только вперёд и не в приседе), присед ~1,6 м/с.
- Прыжок невысокий (~0,6 м): солдат в снаряжении, а не акробат.
- Инерция: разгон и торможение не мгновенные, в воздухе управление слабее.
- Присед — плавное изменение высоты капсулы и камеры; встать нельзя, если сверху препятствие.
- Обзор мышью, вертикаль ограничена ±89°. Esc отпускает мышь, клик — захватывает.
- Покачивание камеры при ходьбе и беге, «просадка» при приземлении, лёгкий крен при стрейфе.
  Сила эффектов регулируется одним множителем (настройка доступности, укачивание).
- Все параметры — `@export`, подбираются в инспекторе без правки кода.

**Состав:**
```
Player (CharacterBody3D, scripts/player/player.gd)
├── CollisionShape3D (капсула, высота меняется при приседе)
└── Head (Node3D) — наклон по вертикали, высота глаз
    └── CameraEffects (Node3D, scripts/player/camera_effects.gd) — покачивание, приземление, крен
        └── Camera3D
```
Player отвечает за физику и ввод; CameraEffects — только за визуальные эффекты и узнаёт о
приземлении через сигнал `landed`. Эффекты можно выключить, не трогая движение.

**Лестницы (решение для всего проекта, ПРЕДЛОЖЕНО P-035):** `CharacterBody3D` в Godot не умеет
подниматься по ступенькам сам. Под каждой лестницей кладём невидимую наклонную коллизию
(пандус), а ступени — только визуал. Это стандартный приём, он дешевле и надёжнее кода «шагания»
и даёт плавную камеру на лестнице. Нужен уже для лестницы больницы в миссии 3.

**Критерии готовности:**
- [x] Тестовая сцена запускается без ошибок и предупреждений.
- [x] Можно пройти по полу, лестнице, проползти в приседе под низким потолком (автотест).
- [x] Под низким потолком нельзя встать (автотест).
- [ ] Создатель оценивает ощущение от движения как «приятно» (подбор параметров).

**Файлы:** `scripts/player/player.gd`, `scripts/player/camera_effects.gd`,
`scenes/player/player.tscn`, `scenes/levels/prototype/test_range.tscn`,
`scripts/debug/debug_overlay.gd`, `tests/test_player_controller.gd`.

**Не входит в v0.1:** выносливость, наклоны (Q/E), перелезание, взаимодействие, оружие, звуки шагов.

## Техописание: меню и настройки v0.1 — В РАЗРАБОТКЕ (объём — D-039)

**Задача:** игру можно запустить «как игру»: главное меню, выбор сцены, пауза, настройки, которые
сохраняются между запусками. Настройки нужны и для плейтестов (чувствительность, FOV, укачивание),
и для слабых машин друзей-тестеров.

**Объём (D-039):**
- Главное меню: «Новая игра» → выбор сцены, «Настройки», «Выход». Становится главной сценой проекта
  (F5); F6 по-прежнему запускает открытую сцену напрямую.
- Выбор сцены (только на время прототипа): все `.tscn` из `scenes/levels/` и `scenes/blockouts/`,
  находятся автоматически — новые уровни создателя появляются в списке без правки кода.
- Пауза по Esc: «Продолжить», «Настройки», «В главное меню», «Выход». Esc больше не отпускает мышь
  сам по себе (замена старого поведения согласована). Работает в любой сцене с игроком, сцены
  править не нужно.
- Настройки, вкладки:
  - **Графика:** режим окна (окно / полный экран / эксклюзивный), VSync, ограничение FPS,
    масштаб рендера (50–100 %, FSR 1 ниже 100 %), пресет качества (низкое / среднее / высокое /
    своё) → качество теней, сглаживание (выкл / FXAA / TAA / MSAA 2× / 4×), SSAO.
  - **Звук:** общая громкость, музыка, эффекты, голоса.
  - **Управление:** чувствительность мыши, инверсия Y. Поле зрения и сила покачивания камеры
    в настройки не выносятся (решение создателя) — задаются в сцене игрока.
  - **Клавиши:** по два слота на действие; «нажмите клавишу», Esc — отмена, Delete — очистить слот;
    клавиша, занятая другим действием, снимается с него (с подсказкой); сброс по умолчанию.

**Архитектура:**
```
autoload Settings  (scripts/autoload/settings.gd)  — значения, применение, user://settings.cfg
autoload Game      (scripts/autoload/game.gd)      — смена сцен с экраном загрузки, пауза по Esc
scenes/ui/main_menu.tscn      — главное меню + выбор сцены (scripts/ui/main_menu.gd)
scenes/ui/pause_menu.tscn     — меню паузы (создаёт Game, scripts/ui/pause_menu.gd)
scenes/ui/settings_menu.tscn  — экран настроек (scripts/ui/settings_menu.gd), общий для меню и паузы
scenes/ui/menu_theme.tres     — общая тема интерфейса
default_bus_layout.tres       — шины Master / Music / SFX / Voice / Radio→Voice / Ambience→SFX
```
- `Settings` — единственный владелец значений. `get_value(key)` / `set_value(key, value)`, сигнал
  `changed(key)`. Применяет всё, что относится к движку (окно, вьюпорт, шины, InputMap). Игровые
  системы сами читают нужное и подписываются на `changed`: игрок — чувствительность и инверсия. Сохранение — в `user://settings.cfg` при закрытии экрана настроек.
- SSAO лежит в `Environment` уровня, поэтому `Settings` ловит появление `WorldEnvironment`
  (`SceneTree.node_added`) и включает SSAO только при включённой настройке — дизайн уровня при
  этом не меняется, в файл сцены ничего не пишется.
- Пауза — `SceneTree.paused`; меню паузы и экран загрузки работают с `PROCESS_MODE_ALWAYS`.
  Пауза доступна, только если в дереве есть игрок (группа `player`).
- Экран настроек строится кодом из таблицы описаний: новая настройка = одна строка в таблице.

**Критерии готовности:**
- [ ] F5 открывает главное меню; из выбора сцены запускаются площадка и все наброски.
- [ ] Esc в игре ставит паузу; из паузы можно продолжить, открыть настройки, выйти в меню.
- [ ] Все настройки применяются сразу и сохраняются между запусками.
- [ ] Переназначенные клавиши работают в игре и переживают перезапуск; сброс возвращает исходные.
- [ ] Автотест меню и настроек проходит; автотесты контроллера и наборов не сломаны.
- [x] Создатель проверил меню в игре (сессия 28).

**Не входит в v0.1:** «Продолжить» в главном меню (нет сохранений), геймпад, субтитры и язык,
яркость/гамма, фон-сцена и музыка меню, финальный визуальный стиль интерфейса.

## Техописание: звук v0.1 — игрок и окружение — В РАЗРАБОТКЕ (объём — D-040)

**Задача:** мир перестаёт быть немым. Шаги, фон и эхо помещений сразу сообщают, где ты — на улице,
в кафельном коридоре, на лестнице, в подвале. Это основа звукового направления (GAME_VISION:
«тишина как инструмент») и будущего слуха ИИ (противник слышит шаги).

**Объём (D-040):**
- Шаги по типу поверхности: бетон, кафель, асфальт, земля, металл, дерево — по 5 вариантов, без
  повторов подряд, лёгкий разброс высоты и громкости. В приседе тише (−9 дБ), на бегу громче (+3 дБ).
- Прыжок (шорох снаряжения) и приземление (удар корпуса + шаг по поверхности, громкость по скорости
  падения; сход со ступеньки не озвучивается).
- Звуковые зоны: фон (ветер снаружи, гул корпуса, подвал) с плавной сменой и реверберация
  помещения (комната, лестничная клетка, подвал).
- Звуки меню: наведение и нажатие.
- Звуки синтезируются собственным скриптом (как текстуры, P-044): ничего не скачиваем, лицензий нет.
  Это честные заглушки; файлы можно заменить своими с теми же именами — генератор их не перезапишет.

**Архитектура:**
```
tools/audio/build_sounds.py      — синтез .wav (только стандартная библиотека Python)
assets/audio/sfx/footsteps/      — <поверхность>_<n>.wav + <поверхность>.tres (AudioStreamRandomizer)
assets/audio/sfx/body/           — jump_<n>.wav, land_<n>.wav + jump.tres, land.tres
assets/audio/ambience/           — outdoor_wind.wav, indoor_hum.wav, basement.wav (бесшовные петли)
assets/audio/ui/                 — hover.wav, click.wav
scripts/audio/surface_type.gd    — SurfaceType.of(коллайдер) → тип поверхности
scripts/player/footsteps.gd      — узел Footsteps в сцене игрока; сигнал stepped(surface, volume_db)
scripts/audio/audio_zone.gd      — AudioZone (Area3D): фон + реверберация
autoload AudioDirector           — смена фона по зонам с кроссфейдом, звуки интерфейса
шины: + ReverbRoom, ReverbHall, ReverbBasement (→ SFX)
```
- **Поверхность** определяется по коллайдеру под ногами (столкновения `move_and_slide`, нормаль
  вверх): 1) метаданные `surface` на узле или его предках — создатель может пометить любой объект в
  инспекторе; 2) материалы модуля набора (`floor_tile` → кафель, `asphalt` → асфальт и т. д.);
  3) иначе бетон. Результат кэшируется на коллайдер.
- **Шаг** — каждые 1,55 м пройденного по земле пути (совпадает с периодом покачивания камеры).
  Источник — `AudioStreamPlayer3D` у ног без затухания: так на шаги действует реверберация зон.
- **Зона** — `Area3D` со своим фоном и громкостью; реверберация — встроенные свойства Area3D
  (Reverb Bus). Из перекрывающихся зон действует зона с большим `priority`. `AudioDirector`
  переключает фон за 1,5 с; если у новой зоны тот же фон — только меняет громкость, без перезапуска.
- **Звуки меню** — `AudioDirector` сам подключается ко всем кнопкам, появляющимся в дереве; сцены
  интерфейса править не нужно.
- **Разметка:** генератор наброска миссии 3 добавляет зоны: территория (ветер), 1 и 2 этажи (гул,
  комната), лестничная клетка (гул, большое эхо), подвал (подвал, эхо подвала).

**Критерии готовности:**
- [x] Шаги звучат и различаются на кафеле, бетоне, асфальте, земле; тише в приседе, громче на бегу
  (автотест).
- [x] Прыжок и приземление озвучены (автотест).
- [x] В наброске миссии 3 фон и эхо меняются при переходе улица → корпус → лестница → подвал (автотест).
- [x] Кнопки меню звучат (автотест).
- [x] Автотест звука проходит (34/34); остальные автотесты не сломаны.
- [ ] Создатель проверил на слух.

**Не входит в v0.1:** музыка, голоса и радио, двери и предметы, оружие, разовые звуки окружения
(вороны, сирены, капли по событию), заглушение звука стенами (occlusion), дыхание и снаряжение при беге.

## Техописание: модульный набор «Больница» v0.4 — В РАЗРАБОТКЕ

**Задача:** строительные блоки для миссии 3 «Красная зона» (вертикальный срез). Сначала —
архитектура в «чистовой геометрии» без текстур; текстуры и детали — следующим шагом.

**Как создаётся:** скриптами, без ручного моделирования. Скрипты — исходники: правим код,
перезапускаем, всё обновляется. Порядок сборки (из корня проекта):
```bash
B=/Applications/Blender.app/Contents/MacOS/Blender
$B -b --factory-startup --python tools/blender/build_textures.py -- assets/textures/hospital
$B -b --factory-startup --python tools/blender/build_hospital_kit.py -- assets/models/kits/hospital docs/art/hospital_kit_v04.png
python3 tools/hospital_layouts.py           # наброски: палата и служебный блок → scenes/blockouts/
"<Godot>" --headless --path . --import      # импорт новых файлов
python3 tools/fix_texture_imports.py        # настройки 3D-текстур, затем ещё раз --import
```
1. `build_textures.py` — процедурные бесшовные текстуры (цвет, нормали OpenGL, шероховатость),
   `assets/textures/hospital/`. Ничего не скачивается: текстуры собственные.
2. `build_hospital_kit.py` — модели `.glb` (без текстур внутри) + библиотека материалов Godot
   `assets/materials/hospital/*.tres` + превью с текстурами (EEVEE).
3. `hospital_layouts.py` — **наброски** (общие расстановки): палата (`ward_layout`) и служебный блок
   (`service_layout`). По ним пишутся сцены `scenes/blockouts/*_blockout.tscn` и рендерятся превью в
   Blender (_airlock, _dock, _basement), поэтому превью всегда совпадает со сценой.

**Защита ручной работы создателя (D-037):** генераторы не перезаписывают то, что мог доработать
создатель: наброски, правленные вручную (контрольные суммы в `scenes/blockouts/.generated.json`;
флаг `--force`), материалы `.tres` (флаг `--overwrite-materials`), текстуры (флаг `--overwrite`).
Модели `.glb` пересобираются всегда — поэтому модули нельзя переименовывать и менять их привязку.
Инструкция для создателя — `docs/LEVEL_PIPELINE.md`.
4. `fix_texture_imports.py` — VRAM-сжатие, мипмапы и режим нормалей для всех текстур в `assets/textures/`.

**Материалы:** скрипт импорта `scripts/editor/kit_material_import.gd` заменяет материалы модели на
общие из библиотеки по имени — текстура хранится один раз. Он подключён **по умолчанию для всех 3D-моделей
проекта** (`[importer_defaults]` в `project.godot`), поэтому новые модули получают его сами. На модели
без совпадающих имён материалов он не влияет. Светящиеся материалы (светильник) — через `EMISSION`.

**Импорт текстур:** VRAM-сжатие (`compress/mode=2`), мипмапы, у `*_normal` — `compress/normal_map=1`.
Прописано в `.png.import`, потому что фоновый импорт не определяет «3D-использование» сам.

## Бюджет производительности (цель)

- 60 FPS на GTX 1660 / RX 580 уровне при 1080p, Medium.
- До 15–20 активных ИИ-агентов одновременно; массовка — упрощённые NPC без полноценного ИИ.
- Туман, ночь, погода используются и как атмосфера, и как средство сократить дальность прорисовки.

## Производственные решения, снижающие стоимость (предложения)

- **Персонажи в респираторах и шлемах** — лица почти не видны, лицевая анимация не нужна.
  Обосновано сеттингом. Это крупнейшая экономия проекта.
- **Камера только от первого лица**, без внешних кат-сцен.
- **Радио и диалоги на ходу** вместо постановочных сцен с анимацией.
- **Один модульный кит города** (панельки, улицы, КПП), переиспользуемый в нескольких миссиях.
- Анимации: стоковые библиотеки + ретаргетинг в Blender; собственные — только для ключевых сцен.
